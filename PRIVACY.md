# Plexiform privacy notice

Plexiform is a desktop app that watches your AI coding sessions and shows their state as a small light. This page says what it reads, what it keeps, and what (very little) ever leaves your computer. Things that are planned but not built yet are labelled **Not yet shipped**.

## In short

- **On by default:** checking GitHub for pull requests and builds through your own GitHub login (only if you have the `gh` tool signed in), and reading your Focus / Do Not Disturb status on this computer.
- **Off by default:** calendar, calendar subscription link, voice questions to Claude, answering permission prompts from Plexiform, and remote devices.
- **Never:** telemetry, analytics or advertising trackers. We don't sell or share your data.
- **Only if you join a team board:** your cards, handovers and run progress go to your team's hub. Today that hub is run by Plexiform at `app.plexiform.dev`. When you sign in (with Google or GitHub, as accounts roll out), your name and email are shared with that hub.
- **Update checks (Plexiform's servers):** the app asks `download.plexiform.dev` whether a newer version exists, and downloads it from there only when you ask. Like any download, this reveals your IP address and your app version.
- **The website waitlist:** if you join the waitlist on `plexiform.dev`, we store the email you give us.
- **Cloudflare** passes all of this traffic through (the hub, the website and downloads) as our processor.
- **Not built yet:** crash reports (they will be off until you opt in).

## What stays on your machine

- **Plugin review (read-only groundwork).** The verifier checks bundled plugin descriptions and exact local source files. The manifest's `agent-plugins.org` schema identifier is checked locally without contacting that site. Private review plans stay in memory; this stage does not install plugins, change agent settings, contact a provider or save a settings journal.

- **Automatic work-card routing (local lookup).** <!-- flow:work-capture-repository files=src/work-capture.js --> Plexiform reads a reported working folder's local Git origin with a bounded, read-only Git configuration command. It loads its own repository-name normalizer locally; this lookup does not contact GitHub or run project commands. A private file records task identities, their pinned board destinations, remembered repository defaults and whether automatic cards are enabled. It does not read AI transcripts.

Plexiform reads these on your computer and never uploads them:

- Your Claude Code conversation logs (the files in `~/.claude/projects`), read to work out tokens and spend. Only counts and costs are kept, not the text.
- Your prompts and Claude's replies. Plexiform never stores your prompts. Claude Code (and Cursor, Codex or Gemini if you connected them) tells Plexiform through small add-ons called hooks that a prompt was sent or a tool ran, and that feeds the session state below.
- Session state: for each session, the folder it runs in, its state, the current tool name, the model name, task counts, and the labels of agents it started (up to 40 characters of the agent's type or of the description the model wrote). When a turn fails, it also keeps up to 120 characters of the error or of Claude's last reply, which can therefore contain a snippet of Claude's own words.
- Waiting inputs you answer from the widget, only if you turned on "Answer permission prompts from the widget" (off by default). While Claude Code waits for you, Plexiform briefly holds what it is waiting on, in a request file with the request id, session id, folder, tool name, and a fingerprint (SHA-256) that binds your answer to exactly what was shown. What else the file holds depends on the kind:
  - **Permission:** the full tool input (the whole command, file path, web address or agent instructions) and any "allow for this session" suggestions. A command can contain secrets you typed into it.
  - **Plan:** the plan text Claude wants approved.
  - **Question:** the questions and their options.
  - **Elicitation:** the request an MCP server is making of you, including the form it asks you to fill.
  - **Notification and blocked:** not request files. The notification's title and message, or the reason Claude's classifier denied something, is recorded in the session file and only shown.
  - **Dialog:** a startup or permission dialog read from a terminal pane (see below), shown but never answered by Plexiform.
  The request files are readable only by you (mode 0600, in a folder set to 0700) and are deleted when you answer. If you don't answer, the hook removes the file itself when it gives up (about 55 seconds, or 20 for questions), and any left behind is swept after about 75 seconds while Plexiform is running. The key that proves an answer came from Plexiform is held in memory and never written to disk.
- Your settings, rules, and any face photos you add as cameos.
- Git and CI results fetched with your own `gh` login (see the next section).
- Spend: worked out from your Claude Code conversation logs, in a background thread, on your computer. Nothing is sent anywhere.
- Calendar and focus status (see below), and terminal details: to jump to a session's terminal, Plexiform records in the session file the terminal's identifiers (seven environment values, the terminal device, and the folder at session start).
- Voice: your speech is turned into text on your device. Audio is never written to disk and the spoken words are never logged.
- Codex activity, when connected: session and turn identifiers, working folder,
  bounded subagent identifiers, fixed event/tool labels and local receipt times.
  The adapter discards prompts, messages, tool arguments/results and transcript
  paths from hook input. It does not read Codex conversations or provider logins,
  answer permissions or treat a child finishing as its parent finishing.
- Copy diagnostics (Preferences → Health): puts a text report on your clipboard only when you click it: the health check results, the app, Electron and OS versions, and recent startup, warning and error lines from `app.log`. Home paths are replaced by `~`; folder, repo, host and user names are hashed or removed; tokens, keys, email and IP addresses are redacted. It never includes prompts, conversation logs or session contents, and nothing is sent anywhere: you choose where to paste it.

Everything below lives in `~/.claude-traffic-light` on your computer:

- `sessions/`: one small file per live session.
- `owned/`: launch records and claims for sessions Plexiform launched (see below).
- `requests/`: pending permission requests and your answers.
- `config.json`: your settings and rules.
- `stats.json`: per-day and per-project counts, times and costs, keyed by folder name.
- `compaction-stats.json` (only once the compactor has run): for each compaction, the provider name, the time, and the token counts before and after. No message text, summaries or session identifiers. At most the last 100 compactions plus running totals.
- `cameos/`, including `cameos/index.json`: photos you add and their names.
- `characters/`: characters you hatch, one folder each, holding the character's art and the choices you made. They are made from templates on your computer and are never uploaded.
- `git-signals.json`: recent pull request and build events with their titles and links, the ids of events already shown, your GitHub login, branch names, local folder paths and the logins of reviewers. It holds no passwords or tokens.
- `busy-ics-cache.json` (only with a calendar subscription link): event times and the repeat rules, status and free/busy flags of those events, plus a fingerprint (SHA-256) of the link, never the link itself. Meeting titles are kept only if you turned on "show meeting name".
- `away.json`: a recap written after any busy spell, including a Focus one (Focus reading is on by default). It lists session ids, folder paths, tool names, the names of rules that held a notification, and why you were busy: the Focus mode's name, or the meeting's title only if you turned on "show meeting name" (up to 60 characters). It is deleted when you dismiss it or it expires.
- `approval-counts.json`: how often you have approved the same command or folder from the widget, for a "make it a rule?" suggestion. Not written for now: the card is hidden and nothing is counted until rules can answer. It holds keyed fingerprints (HMAC-SHA256) of the tool and command or folder, never the command or path itself, with a count and a time; counts older than 30 days are dropped. File mode 0600.
- `approval-secret.json`: the random key those fingerprints are made with, sealed with the system keychain (Electron safeStorage) where available, otherwise a random salt in a file only you can read (mode 0600). Not created for now, for the same reason.
- `last-hook.json`: only the time of the newest hook event and which agent sent it (such as "claude"), so Preferences → Health can show the last hook event after your sessions end.
- `app.log` and `app.log.old`: diagnostic log. It can contain project folder names, repo names and pull request numbers, file paths (which include your OS username) and notification titles. It never contains prompt text.
- `token` and `port`: the details of the connection on this computer (see below).
- `bin/buddy-hook` (`bin\buddy-hook.cmd` on Windows): a small launcher that Claude Code's hooks call.
- `window-bounds.json`, `manual-override.json`, and first-run marker files.

Electron (the framework Plexiform is built on) also keeps its own app data in `~/Library/Application Support/Plexiform` on macOS, `%APPDATA%\Plexiform` on Windows and `~/.config/Plexiform` on Linux. That is browser-style housekeeping (cache, window state) plus the team sign-in, not session data. Before the rename that folder was called `claude-buddy`: the first time Plexiform starts it copies that folder across, leaves the original where it was, and leaves out the sign-in, which only the old app can read (you sign in again).

## What changes on your computer

Plexiform changes a few things outside its own folder, and removes them when you uninstall:

- **Hooks.** It adds its hooks to Claude Code's settings file (`~/.claude/settings.json`), and to Cursor's or Gemini's own config if you connect them. Hooks run Plexiform's bundled scripts using its application binary or local hook wrapper. Connecting Codex adds lifecycle hooks to `~/.codex/hooks.json`, preserving other hooks and the separate `config.toml` notification command. Codex requires review and trust of new or changed hook definitions before running them. Plexiform does not change that trust or install Codex activity hooks automatically at startup. Configuration alone is not evidence that a session is active.
- **One permission rule in Claude Code's settings.** The installer adds a single rule under `permissions.deny` in `~/.claude/settings.json`: `Edit(~/.claude-traffic-light/**)`. It stops Claude sessions from editing Plexiform's own data folder, so an agent can't tamper with Plexiform's files. Before the first change, Plexiform keeps a one-time backup of your settings file at `~/.claude/settings.json.buddy-backup`; it is never overwritten. The rule is removed when you uninstall or disconnect Claude Code.
- **Claude integration (if you turn it on).** One `claude-buddy` entry in `~/.claude.json`.
- **Open at login** (macOS), if you enable it.
- **The first launch after the rename from the old app**, once. Plexiform asks a running copy of the old app to quit (SIGTERM on macOS and Linux, a close request on Windows), and again on later launches while the old app is still installed. It copies the old app data folder, as above; if anything is already in Plexiform's own folder, that is renamed to `Plexiform.pre-migration-<time>` and kept. It points the old app's own entries in Claude Code's settings, Cursor's, Codex's and Gemini's configs, the `claude-buddy` entry in `~/.claude.json` and `bin/buddy-hook` at Plexiform, leaving entries that run anything else alone. Before it changes one of those files it saves a copy beside it as `<file>.pre-plexiform` (never overwritten; a dated copy if one is already there). It turns Open at Login on for Plexiform if the old app had it set up, and says so. It renames `approval-secret.json` to `approval-secret.json.pre-rename`, as the old one is sealed under the old app's Keychain item, and a new one is made. On macOS it then asks whether to move the old app to the Bin, and only does so if you choose Remove.
- **On another machine you pair as a remote device.** Running `node hooks/remote.js pair` there adds Plexiform's reporter hooks (`emit.js --adapter claude`) to that machine's `~/.claude/settings.json`, leaving its other hooks alone, and saves the pairing in its `~/.claude-traffic-light/remote.json` (readable only by you). `node hooks/remote.js unpair` removes both.

## What leaves the machine and when

- **Remote board connections (optional).** <!-- flow:remote-board-browser files=board/web/js/remote-browser.js --> This hub’s connection pages send your chosen application name, boards, access, expiry and explicit create/revoke decisions to the same hub using your browser session and a CSRF check. A remote MCP application signs in through OAuth and receives an independent grant for the boards you explicitly select. It can receive task text, comments, handoffs, permitted messages and evidence references through those tools; your AI application may send that content to its provider under its own terms. Applications can create tasks, change task text and comment only with collaboration access. These tools cannot launch agents, approve permissions or certify evidence. An application’s label is unverified and appears in staff history. Ordinary browser sign-out leaves remote grants active; revoke them in Your connections. Grants expire within 30 days and fail immediately after account/team deletion, membership removal, board removal, revocation or a restored session epoch. The hub stores opaque capability hashes, bounded public client registration metadata, consent bindings and immutable action IDs/resource pointers. Integration tokens are shown once and remain only in the page’s memory until hidden or left; the hub never stores their plaintext. Account/team deletion removes capability hashes, codes and applicable consent bindings and erases grant application labels. Revoked grant tombstones and pointer receipts remain to preserve truthful history; unauthenticated public client registrations have no account ownership and remain bounded independently. Remote HTTP tools require a configured accounts hub; deployment and each application’s real connection need separate verification. Claude’s remote connector requests come from Anthropic’s servers even when used through Claude Desktop; its setup help is at support.claude.com.
- **Integration fetch SDK (explicit use).** <!-- flow:remote-integration-sdk files=sdk/remote-client.mjs --> An integration that you explicitly run can send closed board-tool arguments to your chosen hub’s fixed `/api/integration/v1` endpoint using its own selected-board integration token. The repository-local SDK keeps the token in memory, omits browser cookies, refuses redirects, bounds request/response JSON and never automatically retries writes. Your integration is responsible for its own token storage and downstream data handling. The shared work-context read exposes bounded current card/repository/participant/provider metadata, relative observation ages, declared paths, advisory overlaps and blocker/next-action references on selected boards. Local activity reports are labeled unverified, and heartbeats and declarations do not prove completed work. It reads no private conversations, logs, environment files or machine folders and cannot start or wake an AI. Pages use temporary signed cursors without storing a new session database; grant and current repository checks apply again at delivery. Installing Plexiform does not run this SDK or enable webhooks.

Plexiform has no telemetry, analytics or crash reporting. Shared board workflows send the content you choose to your team hub. Starting an AI task or using board tools in an AI app can send the task and relevant workspace or board content to your chosen AI provider under your account's terms. These flows, update checks and downloads, and the other outbound connections are listed below:

An explicit workflow preview saves only an inert bounded plan on your team hub: task/version/fence and recipe references, source hashes, selected repository, dependencies, provider/member/budget/plan-review choices and private issuer credential row references. No bearer, transcript, environment or log is stored. Preview makes no provider call and grants no execution or approval. Current scoped reads omit credential references; preview validity is at most24 hours and does not renew on retry. Deleting the issuing or selected target account, or the team, removes its preview snapshots while retaining ordinary task history.

A separate explicit execution preview can also save up to16 human-declared relative paths per workflow step and their hash, bounded to200 characters per path. These are advisory intentions; the hub never opens or locks the named files. When the operator has configured GitHub verification, this preview makes bounded read-only lookups of the selected tasks' captured base references to obtain complete commit identities. An unavailable lookup stays labelled unverified and cannot authorize Start. The preview creates no run or paid attempt. Explicit human Start, Resume and Retry save separate private authority, progress, payload-bound receipts and exact run/evidence/reviewer proofs. They can dispatch the fixed reviewed tasks to currently enrolled ready runners under the existing account, provider, budget and plan-approval policies. Pause prevents future launches; Cancel requests only the exact current ordinary stop and does not claim the external process has stopped. No workflow automatically answers a permission, changes provider, retries paid work, merges a PR or transfers a predecessor's code into its successor. Account/team erasure removes private snapshots and disables any recorded workflow-owned dispatch marker; a minimal dispatch/card/run/fence marker remains to prevent an erased authorization from becoming ordinary runnable work. Reads show only the current selected board and omit private credential references, task briefs and proof payloads.

- **Updates.** <!-- flow:auto-update files=src/updater/index.js,src/updater/service.js,src/updater/download.js,src/updater/electron-updater.js,src/updater/mac-swap.js,src/updater/deb.js --> Plexiform checks Plexiform's download server for a new version 30 seconds after it starts and every 4 hours after. - **Remote devices, sending side (OFF unless you pair a machine).** <!-- flow:remote-reporter files=hooks/transport.js --> When you pair another machine you use, such as a server you SSH into, its Claude Code hooks send Plexiform on your own desktop a short signed message whenever a session changes, plus a heartbeat every 30 seconds if you run it. Prompts, tool inputs, file contents and transcripts never leave that machine. Messages go only to the address you gave when pairing, which is your desktop through an SSH tunnel you open (to a loopback port or a private socket) or over your own Tailscale network. - **Remote devices, receiving side.** <!-- flow:remote-listener files=src/remote-devices.js --> Plexiform accepts signed messages from your paired devices on a port of its own (47173). By default it listens only on this computer's loopback address, which is what an SSH tunnel reaches. If you turn on "Also accept devices over Tailscale", it also listens on the Tailscale address that the Tailscale app reports for this computer, never on your local network or the internet. That port serves nothing but device messages: it can't show your sessions or change your settings. A message is ignored unless it is signed by a device you paired, is less than a minute old and hasn't been seen before, and each device is rate-limited. Device keys are stored in `~/.claude-traffic-light/devices.json`, readable only by you. A pairing code must be used within 10 minutes; it is the device's key, so keep it private. ### Technical details

For readers who want the exact terms:

- "Fingerprint" is a SHA-256 hash.
- "Readable only by you" is file mode 0600, in a folder with mode 0700.
- "Hooks" are the commands Claude Code runs on events; Plexiform's is `bin/buddy-hook`.
- "Asks GitHub" means `gh api` GET requests to api.github.com. Plexiform keeps the ETags GitHub returns in memory only, not on disk.
- "A connection on this computer only" is an HTTP server bound to 127.0.0.1. The no-token page is `GET /status`. The token is the `x-buddy-token` header, and the `port` file records the port. The optional Claude integration is an MCP server.
- "Calendar subscription link" is an ICS feed (also written webcal://). The cache stores event times plus UID, RRULE, EXDATE, STATUS and TRANSP fields.
- "Terminal device" is the tty.
- Voice questions run `claude -p --model haiku` with `--tools ''`, `--no-session-persistence` and `--max-budget-usd 0.05`.

For GitHub, connecting creates a GitHub App by sending a form to GitHub. Plexiform checks that form first: it must go to github.com's own new-app page (for your account, or for the organization the admin named) with the hub's sign-in reference, and hold only the app description the hub built (its name, homepage, read-only permissions and events, and the hub's own callback and webhook addresses). Plexiform then sends GitHub a fresh copy rebuilt from the checked fields, never the page's original bytes, and never writes the form's contents to its log. Any other form is refused and no window opens. That window keeps its own storage for each hub, never the board's, so your hub token is never sent to the provider and the provider's cookies stay out of the board. Before the provider page loads, Plexiform puts one short-lived cookie for the hub's own address in that storage. It holds a random value the hub gave the page, so the hub's callback can tell the sign-in came from you. It expires after 10 minutes, the hub clears it on the callback, and Plexiform deletes it when the window closes. The provider never sees it. The window goes only to https pages on public servers and the hub's own callback page, and a new window the provider's page tries to open is refused (nothing opens, not even your browser). The window's title always shows the site you're on. When the provider sends you back to the hub's callback page, the window closes. A connect window still open 10 minutes after it opened closes itself, and then that window's cookies and storage for the hub are cleared too. Signing out of that hub clears the window's cookies and storage. If you sign out, switch account or switch hub while a connect window is still opening, it doesn't open and the short-lived cookie is deleted.

  - **Slack (source preparation; unavailable until reviewed provider acceptance).** Once offered and explicitly connected, connecting creates a Slack app for that one team in the admin's Slack workspace. Slack's `chat:write` permission would also allow messages everyone in a channel can see, but the hub only posts messages that only the person who used the command or shortcut can see. The app can't read channels, files, email addresses or the member list. Slack sends the hub what someone does with the command or shortcut, signed by Slack, and the hub refuses anything not signed for that team's app or older than five minutes.
    - **What Slack sends the hub.** A `/plex` command arrives with the text typed after it and the person's Slack user id and name, the channel's id and name, and the workspace's id and domain. Using the message shortcut sends the hub the whole message it was used on: its text, formatting, any file details (names and types, not the files), and the id of the person who wrote it. The hub holds that only in memory, to pre-fill the card title in the form, and doesn't store it.

The hub checks Slack's signed answer itself against the signing keys Slack publishes at `slack.com`. Slack also hands back a short-lived sign-in token, which the hub discards unused and never stores. Anyone else gets a fixed message seen only by them: someone not linked is told to link their Slack account in Plexiform; a linked member who can only view the board is told to ask an admin for write access; a member whose access ended while they were using it is told it is no longer active; someone from another workspace (a Slack Connect channel) is told only members of this workspace can use Plexiform. These messages never say who the linked member is. The hub never matches people by email. The link (their Slack user id and workspace id, tied to their Plexiform member) is kept until they unlink it or the admin disconnects Slack; either deletes it.

For the message shortcut, the card holds only the title the member confirmed in the form (pre-filled from the message's first line) and a link to the Slack message; the rest of the message and who wrote it are not stored. The team's log of what the connection did keeps short codes and ids only. Slack's reply addresses (`hooks.slack.com`) are used once to answer and never stored. The connection itself keeps, fixed when it is made and never edited afterwards, the workspace id and name, the Slack app's id, client id and bot user id, and the hub's own web address at that time (kept as a record only; links are built from the hub's current address). To stop one person flooding the hub, it counts each Slack user's commands in memory only, under a keyed hash of their Slack user id; that count is dropped about ten minutes after that person's last command, and whenever the hub restarts. The id itself is never stored, logged or written to the team's log.

If something goes wrong after Slack was answered, or someone sends commands too fast, they get a fixed "couldn't do that" or "slow down" message that repeats nothing they sent. When a member uses the message shortcut, the hub sends Slack the form to show them (`views.open`): the name of the explicitly selected team board and its board id, the message's first line, cleaned of formatting, as the suggested title, and a sealed reference that Slack sends back when the form is submitted: the workspace id, the channel id, the message's timestamp, your Slack user id, a timestamp and a MAC (a keyed signature the hub checks so the form can't be pointed at another message or person). When they submit the form, the hub asks Slack for the permalink to that message (`chat.getPermalink`, naming the channel id and the message's timestamp). Slack text never reaches an agent.

Missing, archived or changed targets pause intake; the hub never chooses another board. The form contains an opaque authenticated connection/settings/member reference; no raw connection configuration is sent to Slack.

Disconnecting deletes the hub's Slack keys; the admin can delete the Slack app from `api.slack.com/apps`.

## How long things are kept

**Local setup inventory.** <!-- flow:borrow-scan-list files=src/borrow/scan.js --> Setups reads only chosen allowlisted configuration sources after an explicit scan. Saved plugin and extension inventories are separately selectable; package listing commands are disabled on the sharing screen. SSH config is off by default. Original bytes stay in main memory. Review decisions bind to the exact saved files and notes, and edits clear approvals. Own-profile export uses an explicit native Save dialog. Activity and borrow receipts describe reported review or application, without proving execution. Team baselines are reminders. Apply and Undo are still being built.

**Local setup transaction worker.** <!-- flow:setups-private-worker files=src/borrow/transaction-worker.js --> The pending Apply and recovery implementation uses a separate local worker running Plexiform's own fixed script, with an empty environment and no command arguments. It processes selected configuration and recovery data through bounded messages to the main process and the fixed native helper. These messages can contain private local values while the worker prepares encrypted recovery records. OS key wrapping stays in the main process. The worker has no provider login, model call or network connection. It retires on lost authority or timeout; uncertain transactions remain available for review. This implementation remains held until real packaged Apply, recovery and Undo acceptance.

**Fixed local setup helper.** <!-- flow:setups-fixed-platform files=src/setups-platform.js --> The pending Darwin runtime checks the installed app and its fixed helper with the OS signature verifier. A bounded, fixed OS metadata command inspects only their containing directories for ACLs; it does not list configuration contents. The runtime then launches only that verified packaged helper, with no shell, command arguments or inherited environment and four private local pipes. The helper reads or conditionally changes only supported selected configuration targets and encrypted local recovery records. No provider command, login or network connection is used. A missing, changed or insecure resource refuses launch. Real packaged acceptance is still required before enabling Apply and Undo.

The separate read-only transaction core is not yet wired to the screen. When invoked by its fixed main-process callbacks, a confirmed plan can record encrypted local before/shared/proposed snapshots in a private app-owned recovery directory. Its random encryption key is wrapped with OS safeStorage; no plaintext key fallback or remote upload exists. Known secrets and explicit locally filled values are masked in preparation previews. Recovery begins locked and requires a new foreground decision for the same OS profile; it can check whether local files still match after sign-out without restoring team access or changing tool files. On restart the local before/proposed previews remain withheld pending their reviewed masking adapter. Incomplete records are retained, within strict storage limits, for manual recovery. Windows remains unavailable until native directory privacy and bounded-reader support is verified. Existing settings backups do not include this store.

- **Automatic work cards.** When automatic cards are enabled in This Mac, Plexiform matches reported local AI work against the current repositories opted into your signed-in teams' boards. An exact writable match receives the card; unmatched or ambiguous work stays on My board. An incomplete team lookup pauses new routing. You can choose a default for future tasks when a repository belongs to multiple boards. Reports send only an installation identifier, bounded session/task identifiers, reported provider and status, scrubbed title, and an optional scrubbed summary when summary sharing is enabled for that hub. Folder paths, transcripts, tool inputs and account credentials are not included. The hub stores keyed hashes of the source identities and keeps the card and mapping across restarts. Reports are not verified execution or completion; a finished report requests review. Human edits take priority. Archived, deleted and explicitly stopped sources retain a tombstone so another report cannot recreate the card. You can pause new reports in This Mac; already shared cards remain on their board.

What the code does today:

- **Stats:** per-day counts and costs are pruned after 60 days.
- **Session files:** swept automatically once they are stale, which is the longer of your "waiting" and "working" stale settings (defaults 4 hours and 6 minutes) plus 12 hours.
- **`app.log`:** rotated at 512 KB into one `app.log.old` file, which is overwritten at the next rotation. So at most about 1 MB of log is kept.
- **Git events:** at most the last 30 events, and "seen" markers are dropped after 2 days.
- **Permission requests:** removed when answered. A leftover request is swept after about 75 seconds and a leftover answer after 10 minutes, while Plexiform is running.
- **Team hub (if you join):** its change journal is append-only (comment bodies are not copied into it). Presence is held in memory only and expires after 90 seconds. The hub host keeps nightly database snapshots, the last 14. Until accounts ship, deletion is on request; when they ship, a code-confirmed delete anonymises your user and revokes every device and session.
- **Busy cache and `away.json`:** `away.json` is deleted when dismissed or expired; the feed cache is overwritten on each fetch.
- **Backups:** 30 days, and no more than about 200 MB in total, oldest first, but the 5 newest are always kept. A backup saved just before a restore is kept for at least 7 days.
- **Everything else** (config, cameos, window position) stays until you delete it.

## Delete your data

Plexiform never deletes your settings for you (it only prunes old backups, as above). The reset actions in the Lights window (Reset rules, removing a face, Replace everything on import) first save a backup. To remove everything yourself:

1. Quit the app from its tray (menu-bar) icon → Quit.
2. Remove the hooks it added to Claude Code (in `~/.claude/settings.json`, or `%USERPROFILE%\.claude\settings.json` on Windows), and the `claude-buddy` entry in `~/.claude.json` if you turned on the Claude integration. Hooks for Cursor, Codex and Gemini, if connected, are in those tools' own config.
3. Delete the folder `~/.claude-traffic-light` (`%USERPROFILE%\.claude-traffic-light` on Windows), which includes `bin/buddy-hook`.
4. Delete the backup folder (`~/Library/Application Support/Plexiform Backups`, `%APPDATA%\Plexiform Backups` on Windows) if you want your settings gone for good, since deleting step 3's folder leaves it behind on purpose.
5. Delete Electron's app data: `~/Library/Application Support/Plexiform` on macOS, `%APPDATA%\Plexiform` on Windows, `~/.config/Plexiform` on Linux, and the same folders named `claude-buddy` (and any `Plexiform.pre-migration-…`) if you used the app before the rename. The `.pre-plexiform` copies beside your agent configs can go too.
6. On macOS, open Keychain Access and delete "Plexiform Safe Storage", and "Claude Buddy Safe Storage" if you used the app before the rename.
7. Uninstall the app the usual way for your system: on macOS drag Plexiform from Applications to the Bin, on Windows use Settings → Apps. Turn off "Open at login" first if you enabled it.
