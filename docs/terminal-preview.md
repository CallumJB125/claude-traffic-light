# Plexiform Terminal: recovered development preview

Status: implemented local development preview, **not a published release**. The approved separate-terminal design lives in the historical `outputs/plan-agent-terminal.md` Revision 3. Previously only PR 0s's contracts and stubs existed. This change adds a working, separate terminal rather than embedding a PTY inside Plexiform or relabeling the external-terminal dashboard.

## What the preview does

- A separate Electron app renders real terminal tabs with xterm.js. It behaves like a normal terminal first: at launch it opens the most recent tab, or starts a login shell in your home folder when there are none. ⌘T and the Shell, Claude and Codex buttons start immediately, with no folder picker, in the selected tab's folder (or the observed agent's folder on its detail page), falling back to home; `cd` as usual. Provider tabs start the user's signed native CLI; no subscription credentials are copied. CLI login and provider permission prompts stay in that tab.
- A Swift Session Keeper owns the PTYs. Closing/reopening the Terminal window preserves the shell's PID and reconstructs its screen. Detach hides a tab without stopping it; Stop requires a native confirmation for the selected tab. A reboot or keeper crash ends these sessions; crash recovery is not implemented.
- Layout (version 0.3.0, polished in 0.3.1): sessions on the left, the selected session in the middle, its agents on the right, and a status line along the bottom.
  - The sidebar lists keeper tabs and Claude/Codex/Gemini/Hermes sessions observed through Plexiform's hooks, grouped Needs you, Working and Idle. Finished and idle sessions with no change for 30 minutes, and exited tabs straight away (the keeper does not report when a tab exited), fold into a closed "Earlier today" line (count, the most common tool, failed exits), so old background rows no longer flood the list. Running shell tabs never fold. Each row shows a status indicator (distinct colour and shape), project folder, tool, what it is doing or waiting on, elapsed time and how many subagents are running.
  - Selecting a keeper row shows its terminal; selecting an observed external row shows a read-only page and never sends input. Either way the rail shows an agent tree: the main agent (status, what the hook says it is doing, elapsed), its subagents (live first; indented under a parent only when the hook names a parent that is also listed; running, waiting, done or stopped, with timing; a waiting subagent shows how long it has waited — from its oldest open approval or question, or from when this window saw it start waiting — and nothing when that is unknown), and bus hand-offs it sent or received. Below that: hand-off cards (Sent, Claimed, Ran, Result; Running, Blocked, Succeeded, Failed or Ended, with the reason the bus gives) and the activity seen since the window opened.
  - Boards (0.3.1): with any team in the picture, each sidebar row, Overview lane and status line says where the session's cards go (a team board's name, My board, or No card) with a short reason (repo linked, from a hand-off, other team's repo, repo not linked, no git remote, folder excluded, marked personal, route pending, …), and the Overview offers a board filter. A solo person sees none of that; only a session that makes no card at all is marked. The board comes from the awareness roster, else from Plexiform's card records (`work-capture.json`: provider, session id, destination and `why` only).
  - The status line shows provider and model, the board its cards go to ("On <team>", "My board" or "No board") with the reason, notes waiting, its bus handle, its state and elapsed time, and the keeper attach state and terminal size.
- The Overview (⌘0) shows totals and one swimlane per live session on a 15/30/60-minute axis, coloured by state, with a sub-lane per subagent. Arrows mark bus hand-offs between sessions; a hand-off to a fresh run is labelled with the provider that ran it, and the label turns inward at the track's edges. Hand-offs that share a trace id are linked: a fallback continues its failed run's label ("→ Codex ✕ ↻ Gemini") or is drawn dashed, and its card says it is a fallback. Notes between sessions are dotted lines ending in a small square, and listed beside the lanes (who and when; never the text). Lane labels are fitted after layout: the full text, else the state's name, else none, so no word is cut off. Beside the lanes are the needs-you queue and recent hand-offs. Lanes show only states reported while the window was open; time before that is drawn dotted as not observed. A subagent that finished before the window saw it start is a mark at its end, not a guessed bar.
- Keyboard: ⌘0 Overview, ⌘1–⌘9 the sidebar rows in order, ⌘J next session needing you, ⌘P quick switch (sessions and new-session commands), ⌘T new shell, ↑/↓ and Home/End within the sidebar and between Overview lanes (Enter opens). If the Session Keeper disconnects, observed agents stay visible and the sidebar offers Reconnect.
- Data is read-only from `~/.claude-traffic-light`: `sessions/*.json` (hook state, bounded, owner-only, no symlinks; prompts, questions, task titles and transcripts are never read into rows), `awareness/roster.json` (bus handle, board and reason, unread-note count from `notices`; ignored unless Plexiform is running and the roster is under five minutes old), `bus-trace.jsonl` plus the Tasks helper's `~/Library/Application Support/Plexiform/tasks/bus-trace.jsonl`, each with its rotated `.1` (read incrementally: only bytes appended since the last look, the bounded tail again after a rotation; hand-off and note lines only: handles, providers, stages and reason codes — the trace never holds a note body or brief; only the `result` line settles a hand-off's outcome), `usage/daily/<month>.json` (spend), `git-signals.json` (CI/PR) and `git status --no-optional-locks` per folder. Each file is parsed again only when its inode, size or modification time changes. Folders are watched (debounced, about 120 ms after a burst of writes), with a 10-second poll as the fallback; a refresh that changes nothing is not sent to the window. Session ids, folders and process ids stay in the main process. Not shown because no file carries them: per-subagent tools, a subagent's start time when it finished before the window opened, exact note counts (the roster lists only notices it has surfaced), hand-offs refused when posted (the trace writes those without a hand-off id, so they cannot be told apart), and history from before the window opened.
- Take-over (version 0.2.0): the app declares `PlexiformTakeover=true` in Info.plist and handles `.command` files (macOS open-file; registered at Alternate rank, so Terminal.app stays the Finder default). Plexiform hands over with `open -a <app> <file.command>`. The file must be an absolute, user-owned regular file (no symlink, ≤256 KB, no control characters in its path) and must not carry the download quarantine flag. Plexiform's own `<tmp>/plexiform-terminal-XXXXXX/continue.command` files run immediately; any other `.command` asks first. Because the keeper only starts Apple-signed login shells, the app — like Terminal.app — opens a new shell tab in the script's folder and types one `exec /bin/zsh -- '<file>'` line into that new tab only. Files that arrive before the keeper connects wait and run after connect or Reconnect.
- Input is accepted only from the current sandboxed Terminal document, for its selected tab, while its window is focused. Multi-line/control-character paste receives a native review. Protocol responses, terminal title commands, external links and clipboard escape sequences are disabled in the renderer. No MCP, agent-bus, hub, phone or remote input API is exposed.

The native C shim stays entirely in async-signal-safe C between forkpty and execve. The keeper's headless emulator is MIT-licensed SwiftTerm pinned to revision `5c83a9d214e7354697624c11deb4e488bdcfabad` (v1.10.1); the renderer is xterm.js 5.5.0 plus fit addon 0.10.0. This follows the final design's separate keeper and xterm app, not the superseded embedded node-pty proposal.

The keeper is the sole DA/DSR protocol responder, both attached and detached. The renderer suppresses those replies during normal output and snapshot replay, so a reattach cannot send duplicate answers. Current-screen cells, colors, cursor, scroll region, application-cursor mode and bracketed-paste mode are reconstructed. Full VT-mode equivalence, image protocols and every provider TUI have not been established.

## Build and run

Current packaged target: **Apple Silicon macOS only**. The configured minimum is macOS 13; older-system runtime acceptance and Intel builds are still pending. Node, the macOS Command Line Tools and Node-API headers are required. No existing app is replaced by this command.

```sh
npm ci
npm --prefix apps/terminal ci --ignore-scripts
npm run terminal:build
```

`terminal:build` runs `node scripts/build-terminal.js --development`. It builds an explicitly marked KEEPER_DEV helper, its audit-token socket addon and an ad-hoc signed app/zip in `dist/terminal/`. Generated Swift dependencies and compiler products are under the neighboring `work/terminal-native-build/` scratch folder, outside the source checkout. Set `PLEXIFORM_NODE_HEADERS` if Node headers are not at `/opt/homebrew/include/node`.

Open `dist/terminal/mac-arm64/Plexiform Terminal.app`. It keeps its own preferences/helper copy in `~/Library/Application Support/Plexiform Terminal Development Preview`; this does not replace Plexiform.app. A private, owner-checked local socket is used. The helper exits ten minutes after it has no connected windows or running sessions. With no existing tabs it starts one login shell in your home folder; it never starts an agent on its own.

The first preview uses keeper build 1 and socket `k1-b1.sock`. A future preview changing keeper behavior must bump both the signed keeper build and rendezvous/copy version. Never overwrite a helper holding live sessions.

## Verification

```sh
npm run test:terminal
npm run test:terminal:native
```

The focused tests cover bounded metadata, omission of private content/control identifiers, symlink/oversize rejection, framed-protocol parsing, channel assignment before coalesced screen bytes, and refusal to turn an unsigned build into a public release.

The native acceptance harness builds an ad-hoc test identity on a unique private temporary socket with a clean HOME. It proves an actual shell receipt, no inherited token canaries, one CPR reply, exact shell PID preservation, a full-screen vi edit surviving driver disconnect/reconnect, exact saved contents, subsequent input, unrelated-peer denial, arbitrary launch-shape denial and control-role denial. It does not use an existing user terminal or an AI provider quota. The fixture driver is never packaged.

The development app also has a fixed packaged acceptance path. It requires both `--lab-state-root=/private/tmp/pf-terminal-lab-<unique>` and `--lab-smoke`, uses that clean home plus an independent socket, starts only its own disposable `/bin/sh`, sends a fixed harmless receipt through renderer IPC, captures the actual visible terminal and writes a JSON receipt/screenshot inside the lab folder. This is a development-only test path, not a general remote-control interface. It stops its own shell and keeper afterward.

`--lab-shots` (with the same `--lab-state-root`) is the matching fixed screenshot pass: it starts one disposable shell in the lab folder, writes its PID to `lab-shell.json` so a driver can link fixture sessions to it, waits for `lab-shots.go`, captures the session, Overview and read-only views in dark and light into `shot-*.png`, then stops its shell and keeper. It reads only the lab folder's `fixture-metadata` and `fixture-data`.

## Distribution and remaining work

The generated zip is a **local developer preview**. It is ad-hoc signed, not Apple Developer ID signed or notarized. There is no public download URL, automatic updater, upload or promote command for it. `build-terminal.js` refuses a public/signed invocation and never publishes. Its runtime banner remains visible.

The native production path checks peer audit tokens, exact identifiers, same-team signatures and signed build floors. Development builds accept ad-hoc identities on their private development socket; that is a laboratory trust boundary, not production authentication. Public distribution remains blocked until Developer ID/notarization, release entitlements without disabled library validation, current signed rendezvous agreement, per-release build floors, oldest-supported-macOS tests, full load/crash/TCC testing and independent security review pass. The existing Plexiform release workflow does not publish this package.

The preview does not yet implement authenticated Plexiform control-client takeover, `rows.publish`, exact external-session jump, chat-to-terminal-to-chat handoff, Terminal auto-update or public website downloads. These operations refuse instead of silently falling back or treating an observed session as controllable. Actual fresh Claude/Codex terminal opt-in and response acceptance remain separate from the disposable shell/editor evidence.
